## 1. 故障排查（单文档检索）

> **考察点：能否从故障手册中定位到正确的错误码并给出结构化排查步骤**

**提问**：我的同步任务一直报 CONN_TIMEOUT，应该怎么排查？

**回答**：

> 根据您提供的报错信息，`CONN_TIMEOUT` 通常表示网络连接尝试超时。以下是排查 `CONN_TIMEOUT` 的步骤：
>
> 1. **检查网络连通性**：
>    - 在数据面 Worker 所在机器上执行 `telnet 10.0.1.20 3306`，验证是否能成功连接到目标数据库的指定端口。如果 `telnet` 命令返回 `Connection refused`，则表示目标端口没有服务在监听。
>
> 2. **确认安全组和防火墙设置**：
>    - 确认已放行 CloudFlow Worker 的出网 IP 段。您可以在 CloudFlow 控制台的「网络诊断」页面查看当前 IP 段。
>    - 检查目标数据库的安全组规则，确保已开放相应的出站规则。
>
> 3. **检查数据库监听设置**：
>    - 确认目标数据库的 `bind-address` 设置为 `0.0.0.0`，以允许来自任何 IP 地址的连接。
>
> 4. **检查连接数限制**：
>    - 使用 `SHOW STATUS LIKE 'Threads_connected';` 命令检查当前的连接数是否接近 `max_connections` 设置。
>
> 根据知识库中的信息，`CONN_TIMEOUT` 的问题通常由网络不通或安全组/防火墙未放行引起，这两种情况占 `CONN_TIMEOUT` 的 **80% 以上**。
>
> 如果以上步骤均未解决问题，请提交工单并附带运行实例 ID 与完整报错日志，以便进一步诊断。
>
> **提交工单时必须提供的信息**：
> - 运行实例 ID
> - 错误码
> - 完整报错堆栈
> - 问题发生时间
>
> 希望以上信息对您有所帮助。如有其他问题，请随时联系技术支持。

## 3. 跨文档综合（多跳推理）

> **考察点：需要同时检索「连接器清单」「套餐说明」「产品概述」三份文档才能完整回答**

**提问**：我要把 MySQL 的数据实时同步到 Snowflake，需要开通什么套餐？怎么配置？

**回答**：

> 根据提供的知识库信息，以下是关于将 MySQL 数据实时同步到 Snowflake 的相关信息：
>
> ### 1. 套餐要求
> - **最低套餐**：专业版
> - **支持实时同步（CDC 实时同步）**：MySQL 需开启 binlog 且格式为 ROW
> - **Snowflake 支持**：仅目标，不支持增量同步和 CDC 实时同步
>
> 因此，您需要开通 **专业版** 及以上套餐，并确保 MySQL 数据库已开启 binlog 且格式为 ROW。
>
> ### 2. 配置步骤
> 1. **进入控制台**，点击左侧导航 **「连接管理」→「新建连接」**。
> 2. **选择数据源类型**：选择 **MySQL**。
> 3. **填写连接信息**：
>    - 数据源名称
>    - 数据源类型：MySQL
>    - 主机地址
>    - 端口号
>    - 用户名
>    - 密码
>    - 需要开启 binlog 且格式为 ROW
> 4. **新建目标连接**：
>    - 目标类型：Snowflake
>    - 填写目标连接信息，包括：
>      - 主机地址
>      - 端口号
>      - 用户名
>      - 密码
>      - 配置 Warehouse 与 Role
> 5. **创建同步任务**：
>    - 选择 **CDC 实时同步** 模式
>    - 配置源端与目标端的表映射关系
> 6. **启动同步任务**。
>
> ### 注意事项
> - 确保源端数据库的网络放通了 CloudFlow 数据面 Worker 的访问。
> - 源端数据库账号具备 `SELECT` 权限；若使用 CDC，还需 `REPLICATION SLAVE` 与 `REPLICATION CLIENT` 权限。
>
> 如需进一步的帮助或遇到问题，请提交工单或联系技术支持。

## 4. API 文档（结构化信息）

> **考察点：能否从 API 文档中提取必填字段并组织成可用的调用示例**

**提问**：怎么用 API 创建一个同步任务？哪些字段是必填的？

**回答**：

> 根据提供的知识库信息，创建同步任务的 API 请求体中包含多个字段，其中一些字段是必填项。以下是创建同步任务的详细步骤和必填字段：
>
> ### 1. 创建同步任务的 API 请求
>
> 使用 `POST /v2/sync-tasks` 接口来创建同步任务。请求体中包含以下字段：
>
> ```json
> {
>   "name": "order-db-to-snowflake",
>   "source": {
>     "connection_id": "conn_8a2f",
>     "table": "orders",
>     "mode": "INCREMENTAL",
>     "incremental_column": "updated_at"
>   },
>   "destination": {
>     "connection_id": "conn_3b91",
>     "table": "orders_sync",
>     "write_strategy": "UPSERT",
>     "primary_key": ["order_id"]
>   },
>   "schedule": "0 */1 * * *",
>   "parallelism": 8,
>   "batch_size": 5000
> }
> ```
>
> ### 2. 必填字段
>
> - **name**：任务名称，必填。
> - **source**：源端配置，必填。
>   - **connection_id**：源端连接ID，必填。
>   - **table**：源表名，必填。
>   - **mode**：同步模式，必填。可选值为 `INCREMENTAL`（增量同步）。
>   - **incremental_column**：增量字段，仅在 `INCREMENTAL` 模式下有效，可选。
> - **destination**：目标端配置，必填。
>   - **connection_id**：目标端连接ID，必填。
>   - **table**：目标表名，必填。
>   - **write_strategy**：写入策略，必填。可选值为 `UPSERT`。
>   - **primary_key**：主键字段，必填。
> - **schedule**：调度策略，可选。
> - **parallelism**：并发度，可选。
> - **batch_size**：批处理大小，可选。
>
> ### 3. 示例请求
>
> ```json
> {
>   "name": "order-db-to-snowflake",
>   "source": {
>     "connection_id": "conn_8a2f",
>     "table": "orders",
>     "mode": "INCREMENTAL",
>     "incremental_column": "updated_at"
>   },
>   "destination": {
>     "connection_id": "conn_3b91",
>     "table": "orders_sync",
>     "write_strategy": "UPSERT",
>     "primary_key": ["order_id"]
>   },
>   "schedule": "0 */1 * * *",
>   "parallelism": 8,
>   "batch_size": 5000
> }
> ```
>
> ### 4. 注意事项
>
> - 确保 `connection_id` 和 `table` 等字段的值正确无误。
> - `mode` 和 `incremental_column` 在 `INCREMENTAL` 模式下必须提供。
> - `write_strategy` 和 `primary_key` 在 `destination` 部分必须提供。
> - `schedule` 字段用于指定任务的执行时间，可根据需求调整。
>
> 通过以上步骤和字段配置，您可以使用 API 创建一个同步任务。如有其他疑问或需要进一步的帮助，请随时联系技术支持。

## 6. 安全合规（DOCX/PDF 内容）

> **考察点：能否命中 DOCX 与安全白皮书中的内容**

**提问**：我的业务数据会被 CloudFlow 看到吗？你们有哪些合规认证？

**回答**：

> 根据 CloudFlow 的安全设计，您的业务数据不会经过 CloudFlow 的控制面，也不会在 CloudFlow 侧落盘。具体来说：
>
> 1. **控制面**（CloudFlow 托管）：仅存储任务配置、连接元数据、运行日志，不含业务数据。
> 2. **数据面**（部署在客户 VPC 内）：实际执行数据搬运，数据在客户网络内直接由源端流向目标端。
>
> 因此，即使 CloudFlow 控制面遭受攻击，攻击者也无法获取您的业务数据。
>
> 关于合规认证，CloudFlow 当前持有以下认证与报告：
>
> 1. **ISO/IEC 27001**：信息安全管理体系。
> 2. **ISO/IEC 27701**：隐私信息管理。
> 3. **SOC 2 Type II**：安全性、可用性、保密性。
> 4. **GDPR**：已签署标准合同条款（SCC）。
> 5. **等保三级**：中国网络安全等级保护。
> 6. **HIPAA**：当前不适用，因为 CloudFlow 当前不支持医疗健康数据场景。
>
> SOC 2 Type II 报告可在签署 NDA 后，通过客户经理索取。
