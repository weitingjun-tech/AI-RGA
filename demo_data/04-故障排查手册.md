# CloudFlow 故障排查手册

> 文档版本：v2.4　|　适用套餐：全部　|　最后更新：2026-08-15
>
> 本手册按**错误码前缀**组织。排查原则：**先看错误码前缀定位大类，再按「可能原因」逐条排除**。

---

## 一、错误码总览

| 前缀 | 大类 | 典型场景 |
|------|------|----------|
| `CONN_` | 连接类 | 连不上数据源 |
| `PERM_` | 权限类 | 能连上但无读写权限 |
| `SCHEMA_` | 结构类 | 表结构不匹配 |
| `SYNC_` | 同步类 | 运行中失败 |
| `QUOTA_` | 配额类 | 超出套餐限制 |
| `CDC_` | 实时同步类 | binlog 相关 |

---

## 二、CONN_ 连接类错误

### CONN_TIMEOUT

**报错示例**：`CONN_TIMEOUT: connect to 10.0.1.20:3306 timed out after 30000ms`

**可能原因与排查顺序**：

1. **网络不通** —— 在数据面 Worker 所在机器执行 `telnet 10.0.1.20 3306` 验证连通性
2. **安全组 / 防火墙未放行** —— 确认已放行 CloudFlow Worker 的出网 IP 段（控制台「网络诊断」页可查看当前 IP 段）
3. **数据库未监听外网地址** —— 检查 MySQL 的 `bind-address` 是否为 `0.0.0.0`
4. **连接数打满** —— 检查 `SHOW STATUS LIKE 'Threads_connected';` 是否接近 `max_connections`

**解决方案**：优先排查 1、2 项，这两种情况占 `CONN_TIMEOUT` 的 **80% 以上**。

### CONN_REFUSED

**报错示例**：`CONN_REFUSED: Connection refused`

**含义**：网络可达，但目标端口没有服务在监听。

**排查**：确认数据库服务已启动、端口正确（MySQL 默认 3306，PostgreSQL 默认 5432）。常见于填写了错误的端口。

### CONN_AUTH_FAILED

**含义**：网络可达，但用户名或密码错误。

**排查**：
1. 核对用户名密码（注意密码中的特殊字符是否被转义）
2. 确认该账号允许从 Worker 的 IP 登录：`SELECT user, host FROM mysql.user;`
3. 若是云数据库，确认已将该账号加入白名单

## 三、PERM_ 权限类错误

### PERM_SELECT_DENIED

**含义**：连接成功，但账号缺少表的 `SELECT` 权限。

**解决**：
```sql
GRANT SELECT ON order_db.* TO 'cloudflow_ro'@'%';
FLUSH PRIVILEGES;
```

### PERM_CDC_DENIED

**含义**：CDC 实时同步所需权限不足。

**解决**：MySQL 需授予以下权限后 **重新创建连接**（权限变更不会自动同步到已有连接）：
```sql
GRANT REPLICATION SLAVE, REPLICATION CLIENT ON *.* TO 'cloudflow_ro'@'%';
FLUSH PRIVILEGES;
```

## 四、SCHEMA_ 结构类错误

### SCHEMA_COLUMN_MISMATCH

**含义**：源表与目标表的列不一致（列名、数量或类型不匹配）。

**解决**：
1. 在任务配置页点击 **「重新获取 Schema」**
2. 若目标表由 CloudFlow 自动创建，选择 **「按源表结构重建目标表」**
3. 若类型不兼容（如源 `TEXT` → 目标 `VARCHAR(255)`），需手动修改目标表结构

### SCHEMA_NO_PRIMARY_KEY

**含义**：配置了 **Upsert** 写入策略，但源表没有主键。

**解决**：三选一 ——
- 为源表添加主键（推荐）
- 在任务配置中手动指定 **业务主键**（支持联合主键）
- 将写入策略改为 **Append**

## 五、SYNC_ 同步类错误

### SYNC_OOM

**含义**：同步过程中 Worker 内存溢出。

**解决**：
1. 调小 **批量提交大小（batch_size）**，默认 5000，建议降至 1000
2. 开启 **流式读取（streaming）**
3. 若单表数据量超过 1 亿行，建议先按时间分区拆分任务

### SYNC_DUPLICATE_KEY

**含义**：写入时主键冲突。

**原因**：通常是写入策略选成了 `Append`，但目标表已有相同主键数据。

**解决**：将写入策略改为 **Upsert**。

### SYNC_STALLED

**含义**：任务运行中长时间无进度（默认超过 **30 分钟** 判定为停滞）。

**解决**：
1. 检查源库是否有长事务或锁表：`SHOW PROCESSLIST;`
2. 检查目标端是否在写入时被其他任务加锁
3. 若为偶发，直接 **重跑实例** 即可

## 六、QUOTA_ 配额类错误

### QUOTA_TASK_LIMIT

**含义**：同步任务数量已达当前套餐上限。

**解决**：升级套餐，或停用不再使用的任务释放额度。各套餐任务上限见《套餐与计费说明》。

### QUOTA_ROWS_LIMIT

**含义**：本月同步行数已超出套餐额度。

**解决**：超出部分按 **0.02 元 / 万行** 计费；如需长期使用，建议升级套餐。

---

## 七、CDC_ 实时同步类错误

### CDC_BINLOG_DISABLED

**含义**：源库未开启 binlog。

**解决**：MySQL 需在 `my.cnf` 中配置并重启：
```ini
[mysqld]
server-id        = 1
log_bin          = mysql-bin
binlog_format    = ROW
binlog_row_image = FULL
```
> 必须是 `ROW` 格式，`STATEMENT` 格式 CloudFlow 无法解析。

### CDC_BINLOG_EXPIRED

**含义**：CloudFlow 读取 binlog 的位置已被清理（binlog 保留时间过短）。

**解决**：
1. 调大 binlog 保留时间：`SET GLOBAL binlog_expire_logs_seconds = 604800;`（7 天）
2. 重新初始化该任务，以当前位点重新开始捕获

## 八、通用排查流程

```
任务失败
   │
   ├─ 看错误码前缀
   │
   ├─ CONN_  → 查第二、三节（网络 → 权限）
   ├─ PERM_  → 查第三节
   ├─ SCHEMA_→ 查第四节
   ├─ SYNC_  → 查第五节
   ├─ QUOTA_ → 查第六节
   └─ CDC_   → 查第七节
         │
         └─ 仍无法解决 → 提交工单（附带运行实例 ID 与完整报错日志）
```

**提交工单时必须提供**：运行实例 ID、错误码、完整报错堆栈、问题发生时间。缺少这些信息会显著延长处理时长。
