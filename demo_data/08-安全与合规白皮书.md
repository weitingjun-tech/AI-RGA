# CloudFlow 安全与合规白皮书

> 文档版本：v2.4　|　最后更新：2026-08-15
>
> 本白皮书面向客户的安全与合规团队，说明 CloudFlow 在数据安全、访问控制与合规认证方面的设计。

## 1. 安全架构总览

CloudFlow 采用 **控制面 / 数据面分离** 架构，这是保障客户数据安全的核心设计。

**关键结论：客户的业务数据不会经过 CloudFlow 的控制面，也不会在 CloudFlow 侧落盘。**

- **控制面**（CloudFlow 托管）：只存储任务配置、连接元数据、运行日志，**不含业务数据**
- **数据面**（部署在客户 VPC 内）：实际执行数据搬运，数据在客户网络内直接由源端流向目标端

因此，即使 CloudFlow 控制面遭受攻击，攻击者也无法获取客户的业务数据。

## 2. 数据传输安全

| 环节 | 加密方式 |
|------|----------|
| 控制台访问 | TLS 1.3（强制 HTTPS，HTTP 自动跳转） |
| 控制面与数据面通信 | mTLS 双向证书认证 + TLS 1.3 |
| 数据面到数据源 | 支持 TLS 加密连接（可选，建议开启） |
| API 调用 | TLS 1.3 |

> CloudFlow **不支持** 任何未加密的通信方式，旧版 TLS 1.0 / 1.1 已被禁用。

## 3. 数据存储安全

### 3.1 凭证存储

- 数据源密码使用 **AES-256-GCM** 加密后存储
- 加密密钥由 **AWS KMS** 托管，每 **90 天**自动轮换
- 任何 API 接口均**不返回密码明文**，控制台也只显示掩码

### 3.2 日志脱敏

运行日志在写入前会经过脱敏处理，自动识别并掩码以下内容：

- 密码、Token、密钥
- 身份证号、手机号、银行卡号
- 邮箱地址

## 4. 访问控制

### 4.1 认证

- 支持 **账号密码 + TOTP 二次验证（2FA）**
- 企业版及以上**强制要求**开启 2FA
- 支持 **SSO 单点登录**：SAML 2.0、OIDC

### 4.2 授权

采用 **RBAC（基于角色的访问控制）**，预置角色：

| 角色 | 权限范围 |
|------|----------|
| 所有者 Owner | 全部权限，含计费与成员管理 |
| 管理员 Admin | 任务、连接、成员的完整管理 |
| 开发者 Developer | 创建/修改任务与连接，不能管理成员 |
| 只读 Viewer | 仅查看，不能做任何变更 |

### 4.3 审计日志

- 记录**所有**配置变更与登录行为
- 审计日志**不可篡改**（追加写入，WORM 存储）
- 保留期：企业版 **180 天**，旗舰版 **365 天**
- 支持导出为 CSV 或通过 API 拉取

## 5. 合规认证

CloudFlow 当前持有以下认证与报告：

| 认证 / 报告 | 状态 | 说明 |
|-------------|------|------|
| **ISO/IEC 27001** | 已通过 | 信息安全管理体系 |
| **ISO/IEC 27701** | 已通过 | 隐私信息管理 |
| **SOC 2 Type II** | 已通过 | 安全性、可用性、保密性 |
| **GDPR** | 符合 | 已签署标准合同条款（SCC） |
| **等保三级** | 已通过 | 中国网络安全等级保护 |
| **HIPAA** | 不适用 | 当前不支持医疗健康数据场景 |

> SOC 2 Type II 报告可在签署 NDA 后，通过客户经理索取。

## 6. 数据主体权利（GDPR）

针对 GDPR 要求的数据主体权利，CloudFlow 提供：

- **访问权**：数据主体可请求导出其个人数据
- **删除权**：支持「被遗忘权」请求，通过 API 触发源端/目标端数据清理
- **数据可携权**：支持导出为 JSON / CSV
- **处理限制**：支持对特定字段配置脱敏规则

由于 CloudFlow 数据面运行在客户环境，**CloudFlow 本身不构成 GDPR 意义上的「数据控制者」**，而是「数据处理者」。

## 7. 安全事件响应

| 阶段 | 响应时限 |
|------|----------|
| 事件确认 | 1 小时内 |
| 客户通知 | 确认后 **24 小时内** |
| 初步分析报告 | 72 小时内 |
| 完整根因报告 | 14 个工作日内 |

安全事件可通过 `security@cloudflow.io` 报告，该邮箱 **7×24 小时**值守。

## 8. 渗透测试与漏洞管理

- 每年至少进行 **1 次**第三方渗透测试
- 提供公开的 **漏洞赏金计划**（Bug Bounty）
- 高危漏洞修复时限：**72 小时**内发布补丁

## 9. 私有化部署的安全增强

旗舰版支持将控制面完整部署到客户自有 Kubernetes 集群，此时：

- 全部数据（含元数据）**完全不出客户网络**
- 支持对接客户自有的 KMS 与 SSO
- 可完全离线运行（Air-gapped 模式）
